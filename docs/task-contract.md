# 任务定义与推进约定

任务先按主要操作分类，单臂/双臂、单手/双手另记。五个难度维度是抓取容差、负载与重心、转矩要求、接触切换、双手协同，尚未给出经过实验验证的等级

每项固定身份ID，不因换后端或改目录而改名。改变目标、初态范围、接触约束或成功条件时，要另记协议版本；拆分子任务不与原整项成绩直接比较

## 来源

original：原仓库已有任务；只表示选中了它，不表示可直接换手运行
subtask：从原长任务拆出阶段，需要独立定义起止和通过条件
adapted_subtask：同时改了操作部位或其他语义
internal：团队内部任务，来源以内部版本和资产清单登记
proposed：待找到实现或自行构建，不能把相关资产链接当作现成任务

例如R01扳手紧固目前是proposed：Bench2Dex22链接只确认扳手搬运资产。H01/H02/H03同属手内重定向能力，但原手型、动作接口与评分可能不同，目前不能将差异仅归因于物体几何；蛋形物体不是柔性或易碎模型

## 状态

selected：候选已记录，允许评分、资产和版本未知
source_reviewed：固定源版本，并记录原始成功条件与对应代码
scene_ready：资产清单、机器人映射、加载重置证据可查
smoke_executed：运行链路完成，结果可以失败或未知
baseline_verified：在明确协议下验证参考控制，保存运行输入、版本和结果；不代表已证明泛化、真实性或跨后端一致

UniLab接入单独记录，不能用smoke状态代替。状态检查工具只能检查声明字段，不会自动复跑或审计证据真实性。字段写了 evidence 不等于可以凭空宣称完成，人工推进前仍须核对原始记录

先沿用原任务评分，不默认禁止掌面，不默认要求工具完全低于盒沿，不把新设阈值写成官方规则。诊断指标先作为额外记录。缺失值写null；不支持的接触数据不能填0

资产清单后续必须包含源URL、版本/哈希、许可、单位、尺度、惯性、碰撞几何和关节连接；机器人映射须包括关节顺序、动作语义、控制频率与控制器参数
